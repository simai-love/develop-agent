# 研究開発タスクの計画と検証

このスキルはローカル GUI から指定されたときに使う。GUI はプロジェクト内のタスクごとに計画画面（01）と検証結果画面（02）を持つ。タスクは何段階でも子を持てる。01 でユーザーと要件を固め、ユーザーが「実装に進む」を確認したら実装と最初の検証を続けて行う。02 のチャットでは、結果について相談し、必要ならコードを直して再検証する。子を持つタスクでは、全子タスクの完了後に 02 で結果を総括する。タスクとプロジェクトの完了はユーザーが決める。

現在のタスクの保存先は `tasks/<id>/`。01 の計画は `plan.md` に保存する。実装後および 02 の新しい検証結果は、その実行分だけを `report-draft.md` に書く。GUI が成功した実行の原稿を `reports/0001.md`、`reports/0002.md` のように順番に保存し、過去のレポートは残す。既存タスクの `result.md` は過去のレポートとして扱う。検証用スクリプトは `validation/`、画像・動画・測定データは `evidence/` に置く。番号付きレポート内の資料リンクは保存先から見た `../evidence/<filename>` とする。画像を作った場合は自分で体裁を確認し、内容の解釈を今回のレポートに書く。JSON 応答は画面表示と状態判定に使い、Markdown の本文は含めない。

- 01 のチャットでは [計画の指示](references/01-plan.md)と[計画のひな型](assets/plan-template.md)を使う。
- 「実装に進む」では保存済み計画に従ってコードを変更し、[検証の指示](references/02-validation.md)と[検証結果のひな型](assets/result-template.md)に従って最初の検証まで行う。
- 02 のチャットでは[検証の指示](references/02-validation.md)と[検証結果のひな型](assets/result-template.md)を使う。依頼に応じて追加検証、コード修正、再検証を行い、新しい結果が得られた場合だけレポートを追加する。
- 作業が独立して検証できる複数の範囲に広がる場合は、JSON の `child_task_proposals` で子タスク案を返す。ユーザーの承認前に子タスクやブランチを作らない。

【共通指示】
- 01 のチャットでは、指定されたタスクの `tasks/<id>/` 内だけを書き換え、開発コードを変更しない。
- 02 のチャットでは、ユーザーの依頼に必要な場合だけ開発コードを変更し、変更後は必ず検証して結果を記録する。ほかのタスクは変更しない。
- 計画外の実装範囲が見つかったら、その場で実装を広げず、理由と子タスク案を返す。親の総括ではコードを変更せず、子の計画・レポート・commitを根拠に達成点と残課題を書く。
- 02 では選択式の質問を作らない。結果がまだ得られない場合は、その理由と必要な情報をチャットで短く伝え、レポートを増やさない。
- `app/` と `.codex/` は変更しない。`task.json` と `chat_*.json` は GUI が管理するので変更しない。
- Git のコミットとマージは行わない。コミットはユーザーのボタン操作によって実施する。
- 計画画面で実装を開始しない。ユーザーが別途「実装に進む」を確認してから開始する。
