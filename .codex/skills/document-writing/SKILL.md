# 文書作成

文書を新規作成または大幅に改稿するときは、次の順序で進める。既存文書の軽微な修正や短い回答には、この手順を強制しない。ユーザー指定の構成や書式があれば、それを守ったうえで各段階を行う。

## 1. 文書全体の構造を明記する

本文を書き始める前に、想定読者、文書の役割、読み終えた読者に理解・判断・実行してほしいことを特定する。その目的に合う見出しと順序を、文書全体の構成案として明記する。読者が最初に必要とする結論、判断材料、行動を上部に置き、背景や詳細は理解に必要な順で続ける。固定の「目的→背景→取り組み→結論」を当てはめず、文書ごとに最も効果的な構成を選ぶ。

見出し間の論理のつながり、重複、抜け、粒度を点検する。読者が知りたいことに答えられない構成なら、この段階で組み直す。

## 2. 各構造に必要な要素を明記する

各見出しの下に、実際に書く主張、事実、根拠、例、次の行動を具体的に箇条書きする。「課題を書く」のような執筆指示だけで済ませず、その文書の実際の課題を書く。情報が不足している項目は推測で埋めず、確認事項として区別する。

上部の重要情報は、意味や判断に必要な条件を残しつつ最小限の分量にする。後半の詳細は、読者が検証・再現・実行するのに必要な範囲を網羅する。図、表、コード例などが役立つ場合は、載せる位置と何を示すかをこの段階で決める。

## 3. 実際の文章にする

構成案と各節の要素に沿って本文を書く。段落ごとに一つの主題を扱い、見出し、本文、図表が同じ論理の流れを支えるようにする。箇条書きの企画メモをそのまま完成稿として残さない。

## 4. 読者と役割に照らして見直し、構成へ戻る

初稿を読み、想定読者が冒頭で要点をつかめるか、文書の役割を果たせるか、各主張に必要な説明や根拠があるかを確認する。改善点を具体的に整理し、**初稿後は必ず一度、手順 1 の全体構成へ戻る**。必要に応じて見出しの順番や粒度を変え、手順 2 と 3 も更新する。修正稿を同じ観点で再確認し、目的を満たすまで繰り返す。

構成案や節ごとのメモは作業用に保持する。ユーザーが完成文書だけを求めている場合は、最終出力に作業メモを混ぜない。構成案や検討過程を求められた場合は、それらも示す。
