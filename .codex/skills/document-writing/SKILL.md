# 文書作成

文書を新規作成または大幅に改稿するときは、次の順序で進める。既存文書の軽微な修正や短い回答には、この手順を強制しない。ユーザー指定の構成や書式があれば、それを守ったうえで各段階を行う。

## 1. 文書全体の構造を明記する

本文を書き始める前に、想定読者、文書の役割、読み終えた読者に理解・判断・実行してほしいことを特定する。その目的に合う見出しと順序を、文書全体の構成案として明記する。読者が最初に必要とする結論、判断材料、行動を上部に置き、背景や詳細は理解に必要な順で続ける。固定の「目的→背景→取り組み→結論」を当てはめず、文書ごとに最も効果的な構成を選ぶ。

見出し間の論理のつながり、重複、抜け、粒度を点検する。読者が知りたいことに答えられない構成なら、この段階で組み直す。

## 2. 各構造に必要な要素を明記する

各見出しの下に、その節に必要な主張、事実、根拠、例、次の行動を具体的に箇条書きする。「課題を書く」のような執筆指示だけで済ませず、その文書の実際の課題を書く。

上部の重要情報は、意味や判断に必要な条件を残しつつ最小限の分量にする。後半の詳細は、読者が検証・再現・実行するのに必要な範囲を網羅する。図、表、コード例などが役立つ場合は、載せる位置と何を示すかをこの段階で決める。

## 3. 実際の文章にする

構成案と各節の要素に沿って本文を書く。段落ごとに一つの主題を扱い、見出し、本文、図表が同じ論理の流れを支えるようにする。箇条書きの企画メモをそのまま完成稿として残さない。

## 4. 読者と役割に照らして見直し、構成へ戻る

初稿を読み、想定読者が冒頭で要点をつかめるか、文書の役割を果たせるか、各主張に必要な説明や根拠があるかを確認する。改善点を具体的に整理し、**初稿後は必ず一度、手順 1 の全体構成へ戻る**。必要に応じて見出しの順番や粒度を変え、手順 2 と 3 も更新する。修正稿を同じ観点で再確認し、目的を満たすまで繰り返す。

最終稿のみを提出する。

## 進め方の例

次は、チームの週次会議の議事録について保存先の変更を知らせる、架空の文書の例。見出しや分量は、この例を流用せず、実際の文書の読者と役割に合わせて選ぶ。

1. **構成を明記する。** 読者は会議参加者、役割は保存先の変更と次回からの作業を伝えること。構成案を「変更点 → 必要な対応 → 背景 → 保存手順」とする。
2. **各節の中身を具体化する。** 「変更点」には「次回以降に作る議事録をチーム共有フォルダの『会議記録』に保存し、過去の分は移動しない」、「必要な対応」には「作成者が会議当日に保存する」、「背景」には「個人フォルダでは欠席者が探しにくい」、「保存手順」には「ファイル名を `YYYY-MM-DD_週次会議.md` にする」と書く。図は不要と判断する。
3. **初稿を書く。** 各節を文章にする。

   ```markdown
   # 週次会議の議事録の保存先

   ## 変更点
   次回の週次会議から、議事録はチーム共有フォルダの「会議記録」に保存します。

   ## 必要な対応
   議事録の作成者は、会議当日に保存してください。

   ## 背景
   個人フォルダでは、欠席者が議事録を探しにくいためです。

   ## 保存手順
   ファイル名は `YYYY-MM-DD_週次会議.md` とします。
   ```

4. **構成に戻って直す。** 初稿を読むと、手順 2 で挙げた対象範囲が抜けており、過去の議事録も移動するのか分からない。最初の見出しを「対象と変更点」に変え、対象範囲を冒頭に加える。修正稿全体を読み、必要な対応と手順がつながっているか再確認する。

   ```markdown
   # 週次会議の議事録の保存先

   ## 対象と変更点
   次回以降の週次会議で新たに作る議事録は、チーム共有フォルダの「会議記録」に保存します。過去の議事録は移動しません。

   ## 必要な対応
   議事録の作成者は、会議当日に保存してください。

   ## 背景
   個人フォルダでは、欠席者が議事録を探しにくいためです。

   ## 保存手順
   チーム共有フォルダの「会議記録」を開き、`YYYY-MM-DD_週次会議.md` という名前で保存します。
   ```
