# ホーム画面・HTML 文書・ファイル参照の実装計画

2026-11-14 にユーザーと合意した仕様。3 つの作業 (A/B/C) を並列に実装し、`feature/home-html-files` で統合してから `dev` へ `--no-ff` でマージする。

「プロジェクト」= 画面左で選ぶリポジトリ（`develop-agent` と `repositories.local.json` の登録分）。

## A. plan / report を HTML で書く

- 新規タスクの計画は `tasks/<id>/plan.html`、レポート下書きは `report-draft.html`、保存レポートは `reports/NNNN.html`。
- 既存タスクの `plan.md`・`reports/*.md`・`result.md` は変換せず、従来の Markdown 表示で読める（`plan.html` が無く `plan.md` がある場合は md を使う）。
- Agent への指示・テンプレート（`.codex/skills/research-workflow/` の SKILL.md、references、assets）を HTML 版に改める。文字だけの文書を避け、構成図・流れ図・比較表・結果グラフをインライン SVG や表で入れ、本文は短くする。文字を書くこと自体は問題ない。
- HTML は `<script>` 不可。表示は `sandbox`（スクリプト無効）の iframe（`srcdoc`）で行い、高さは内容に合わせる。画面の CSS 変数に合う最小限の基本スタイルを GUI 側で差し込む。
- 計画の編集は HTML ソースの編集になる（「HTMLを編集」）。`plan_hash` は保存中の計画ファイル本文に対して計算する。
- 計画の要点抽出（目的・確認したいこと）は HTML の見出しからも取れるようにする。

## B. ホーム画面・メモ・plan 承認・定時の担当 Agent

### ホーム画面
- ⌂ ホームで開く。登録済みの全プロジェクトのタスクをプロジェクトごとにカードで表示（Notion のボード風）。
- カード: タイトル、ステータスのチップ、親タスク名、更新日時、plan 承認バッジ。クリックでそのプロジェクトに切り替えてタスクを開く。
- 絞り込み「すべて / 未完了 / 完了」と並び順「更新日時 / 作成日時 / ステータス」。選択はブラウザに保存してよい。
- プロジェクトごとに担当 Agent（CLI と モデル）を設定できる。初期値は Codex の既定モデル。
- 日報一覧（日付ごと）と夜間実行の記録を表示し、日報 HTML を開ける。

### ステータス
`display_status` を拡張し、各タスクの段階が一目で分かる表示にする: 未着手 / 計画中 / 質問あり / 承認待ち（Agent が実装可と判断、未承認） / 承認済み（夜間実行待ち） / 実行中 / 検証中 / 確認待ち / 完了。ホームとタスク画面で同じ表示を使う。

### plan 承認
- 「実装に進む」とは別に「計画を承認」ボタン。Agent の readiness が有効（`can_implement`）な計画だけ承認できる。
- `task.json` に `plan_approval: {plan_hash, approved_at}` を保存。計画が変わり hash が一致しなくなったら承認は無効。承認の取り消しも可能。
- 夜間に自動実行した計画の hash を `auto_run_plan_hash` に記録し、同じ計画を二度自動実行しない。

### メモ
- ホームでプロジェクトごとにメモを登録・編集・削除（タイトルと本文）。
- フラグ「plan 作成 → 実装を Agent に許可」。
- 夜間にタスク化したメモは `task_id` を持ち「タスク化済み」と表示する。

### 定時実行（サーバー内スケジューラ）
- GUI サーバー内のスレッドで動かす。停止中で逃した回は次回起動時に 1 回だけ実行する（最後の実行日時を保存）。
- 毎日 0:00（夜間）、プロジェクトごとに担当 Agent が機械的に判定して実行する。判定対象がなければ何もせず、報告も不要。
  1. 未完了・非実行中で、有効な `plan_approval` があり、`auto_run_plan_hash` と承認 hash が異なるタスク → 実装（実装済み・検証中なら同じ計画での追加実験として実行）を開始。
  2. 許可フラグ付きでまだタスク化していないメモ → ルートタスクを作成（専用ブランチ）、メモ本文で 01 の計画チャットを実行して `plan.html` を作る。Agent が実装可と判断したら、メモのフラグを承認とみなして `plan_approval` を付け、実装まで実行する。質問が残れば計画中で止める。
  - 実行は 1 プロジェクト内で順番に行い、各 run の終了を待つ。
- 毎日 6:00（朝）、前日（0:00–24:00）に `updated_at` が変わったタスク、または夜間実行の記録があるプロジェクトだけ、担当 Agent が日報を HTML で作成する。`.codex/skills/document-writing/` の手順を参考にし、図や表で要点を示す。
- 保存先: 各プロジェクトのタスク記録ルート直下の `.home/`（`memos.json`、`agent.json`、`scheduler.json`、`daily-reports/YYYY-MM-DD.html`、`nightly/YYYY-MM-DD.json`）。`tasks/` なので Git 管理外。

## C. プロジェクト内ファイルの参照（閲覧のみ）

- タスク画面ではそのタスクの作業ツリー（worktree、無ければリポジトリ本体）、ホームではリポジトリ本体を参照する。
- ツリー表示（遅延読み込み）＋ファイル内容表示。テキストは行番号付き、画像はプレビュー、HTML はソース表示と sandbox iframe のプレビュー切替。大きなファイル・バイナリは先頭のみ／ダウンロードのみ。
- `.git` は除外。ルート外へのパス（`..`、シンボリックリンク経由）を拒否する。書き込み API は作らない。
