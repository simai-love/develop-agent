# ローカルGUIの構成

## ディレクトリ

- `app/`: Python標準ライブラリによるローカルHTTPサーバーとGUI。外部サービスなしで動作する。
- `.codex/`, `AGENTS.md`: 本アプリを扱うAgent向けの指示。
- `docs/`: アプリやソースコードの設計資料。
- `scripts/`: 起動など開発者向けの操作。
- `tasks/`: GUIが作成するローカルのタスク記録。`.gitignore` で除外する。
- `projects/`: プロジェクトのブランチ・状態・初回タスクの記録。`tasks/` と同様に Git から除外する。

## タスクの保存形式

各タスクは `tasks/<id>/` に `task.json`、`plan.md`、`reports/`、`chat_plan.json`、`chat_result.json`、`evidence/` を持つ。Agent は結果が得られた実行分を `report-draft.md` に書き、GUI が `reports/0001.md` 以降へ保存する。旧形式の `result.md` があるタスクでは、その内容を最初のレポートとして表示する。検証用スクリプトは必要に応じて `validation/` に置く。チャットファイルは初回利用時に作成される。`task.json` がタイトル、親タスクID、状態、実装可否判定、選択モデル、実装と検証の結論、レポート一覧と各回の変更ファイル、日時の保存元になる。Markdownは人が読める計画と検証結果に使う。`evidence/` は画像、動画、測定データをタスク別に保存する。

状態は `planning`（仮説構築中）、`ready`（実行待ち）、`implementing`（実装中）、`verifying`（検証中）、`completed`（完了済み）とする。状態は表示専用で、Agentの判定、CLI実装、検証後の完了操作によって更新する。計画の文字数では実装可能と判断しない。Agentが最新の保存計画を実装可能と判定したときだけ実装APIを受け付ける。計画・CLI・モデルの変更は判定を失効させる。葉の完了には実装・検証とユーザー承認によるコミットが必要。親の完了には全子の完了、総括レポート、ユーザー承認による上位ブランチへのマージが必要。プロジェクトは全タスク完了後にユーザー承認で `dev` へマージする。

一覧と詳細画面には、保存済みの工程から求めた操作上の状態を表示する。Agentの実行中は「実行中」、完了操作後は「完了済み」、最新の質問への回答・実装開始・検証結果の確認が必要な場合は「ユーザー待ち」とし、次の操作も添える。新規作成直後は「未着手」とする。表示はAPI応答時に最新のチャットと実行情報から求め、タスクの保存形式は変更しない。

タスクの削除では対象と全子孫の `tasks/<id>/` を削除する。詳細画面と左のタスク一覧から子タスク追加・削除を操作できる。確認画面で子タスク数と記録の削除を知らせ、対象のどれかでAgentが実行中ならAPI側で拒否する。`src/` などの開発コードは削除しない。新しいCodexタスクとCodexへ切り替えたタスクには `gpt-6-sol` を保存する。起動時にはモデル未設定で未完了の既存Codexタスクにも同じモデルを設定し、実装可否の判定を失効させる。完了済みタスクの過去のモデル記録は変更しない。モデルの選択肢はCodex CLIの app-server `model/list` から非表示候補を除いて取得し、保存済みモデルが一覧外でも従来の設定を表示する。Codexのモデルが未選択ならチャットと実装開始を無効にし、一覧を取得できなければ画面更新を案内する。Claude Codeではモデル欄を隠し、CLI側の設定を使用する。候補が返ることはアカウントでの実行権限を保証しない。

開発項目の名称変更は `task.json` の `title` を更新する。タスクIDと保存先は維持し、Agent実行中は名称変更を受け付けない。

## 今回の境界

新規プロジェクトは `dev` から `project/<slug>-<id>` を作り、初回タスクを自動作成する。タスクは何段階でも子を持てる。最初の子を作るときだけ親に `task/<id>` ブランチを作る。コード作業はブランチ別の worktree に置き、同じブランチの未コミット変更は一つのタスクへ予約する。Agent が分割を提案した場合、GUI が保存してユーザー承認後に作成する。親の総括はコード変更を伴わず、子の完了 commit とブランチ HEAD を根拠にする。Git 操作の状態は `projects/<id>/operations/` に記録して再起動時に照合する。

既存の最上位タスクは ID と記録を保ったままプロジェクトで包む。元の作業ツリーが dirty なら移行先を確認待ちにし、元の変更を整理してから `dev` の現在の HEAD に移行先を合わせる。
移行前に検証済みで新しい差分がない葉タスクは、ユーザー確認後に履歴上の完了として保存し、新規コミットを要求しない。

Web UI が起動する Codex CLI は `workspace-write` で実行し、検証用のローカル通信に必要なネットワークアクセスを許可する。

計画は書式付きプレビューを通常表示し、編集ボタンでMarkdown原文に切り替える。検証レポートとチャット本文も同じ安全な描画処理で見出し、強調、リスト、表、コード、資料リンクを表示する。01 の各質問には選択肢と自由記述欄を表示し、どちらか一方または両方で回答できる。質問数に固定の上限は設けない。

Agentチャット欄は画面幅いっぱいに配置し、下端の操作部で高さを調整する。高さはブラウザの `localStorage` に保存し、タスクと画面を切り替えても同じ設定を使う。

Agentの実行中はチャット欄の直上に処理内容を表示する。画面が保持する実行情報から計画作成・実装・追加検証を区別し、画面更新後は `task.json` の実装状態を使う。画面更新によって実行IDを失ったときはタスクを定期的に読み直し、完了後に案内とレポート表示を更新する。

タスクの作成、階層表示、計画と検証レポートの保存、状態変更、Codex CLIまたはClaude Code CLIのチャット、実装依頼、完了操作を実装する。01 のチャットはタスク内の `plan.md` を更新し、開発コードには触れない。実装ボタンはコード変更後に最初の検証を実行し、最初のレポートを作る。02 のチャットは追加検証に加え、依頼に必要なコード修正と再検証を行う。結果が得られた実行ごとに新しいレポートを追加し、02画面のトグルで各回の結論と本文を閲覧する。保存済みレポートは画面から上書きせず、追加の確認や訂正は新しいレポートに残す。結果がない依頼ではレポートを増やさず、理由をチャットに返す。選択式質問は01だけで扱う。CLI は画面別の JSON Schema で短い報告と判定を返し、GUI は保存された Markdown を読み直す。01 のチャットは対象タスク、実装と 02 のチャットは所属ブランチの worktree を作業場所にする。選択モデルはCLIの `--model` に渡す。実装開始は確認ダイアログを経る。検証資料は100 MBまでの許可形式をアップロードでき、画像と動画はGUIで表示する。Codexの検証チャットには最大4枚の新しい画像を添付する。動画の内容をAgentが未確認なら結果にも未確認と記載する。各コード変更の前後でGit管理対象および未追跡ファイルの差を確認し、変更ファイルをタスクに累積して保存する。02 の修正が失敗した場合は完了操作を無効にし、02 のチャットから再依頼できる。完了ボタンで Git コミットまたは `--no-ff` マージを実行し、成功後に完了状態を保存する。グラフ表示と詳細なGit差分表示は後続の実装対象。
