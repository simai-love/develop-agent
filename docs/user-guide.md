# 利用ガイド

このアプリでは、研究開発の作業をタスクとして記録します。各タスクには作業ブランチ（コード変更の履歴をほかの作業から分ける場所）があり、必要なら子タスクへ分けられます。画面の「01」で計画し、「02」で検証結果を確認してから完了を決めます。

## 利用前の準備

[README](../README.md#環境構築と起動)の手順で起動し、Agent CLI の認証とモデルの選択を済ませます。チャット欄の「CLI」で Codex と Claude Code を切り替えられます。Claude Code のモデルは「既定（CLI設定）」か Fable・Opus・Sonnet・Haiku から選びます。各候補には CLI が現在使うバージョン（例: Opus 5.5）が表示されます。リポジトリには `dev` ブランチが必要です。

## リポジトリを選ぶ

画面左の「リポジトリ」で `Develop Agent` と `GPU Solver` を切り替えられます。選択先のタスク一覧、計画、レポート、資料、作業ブランチが表示されます。タスク記録はこのアプリの `tasks/` に、追加リポジトリでは `tasks/<リポジトリID>/` に保存します。新規タスクのフォルダ名には作成日時・タスク名・IDが入ります。既存のID名フォルダはそのまま使います。コード変更と Git 操作は選択先のリポジトリで行います。選択はブラウザに保存され、次回も引き継がれます。

新しい作業先は「＋ リポジトリを登録」から選びます。`~/prog` 直下にある未登録の Git リポジトリで、`dev` ブランチを持つものが候補に表示されます。候補を選ぶと表示名が入るので、必要なら編集してください。`~/prog` 以外の場所は「その他の場所を入力」から絶対パスを指定できます。WSL の GPU と HPC SDK を Agent で使う場合はチェックを付けてください。登録内容は Git 管理外の `.codex/repositories.local.json` に保存されます。別の端末で手動登録する場合は、次の内容で作り、`path` をその端末の絶対パスに変えてください。

```json
[{"id":"gpu_solver","name":"GPU Solver","path":"/home/kosuke/prog/gpu_solver","gpu":true}]
```

GPU Solver のアプリはこのリポジトリから起動します。GPU リポジトリはコード作業先として選び、タスク記録はこのアプリの `tasks/gpu_solver/` で管理します。移行前の GPU リポジトリの `tasks/` はバックアップです。既存タスクを再移行する場合は、現行データを先に退避し、元データの絶対パスとシンボリックリンクを新しい保存先へ合わせてください。

## ホームで全体を見る

上部の「⌂ ホーム」で、登録済みの全リポジトリのタスクをプロジェクトごとのカードで一覧できます。カードにはタスク名、段階、親タスク名、更新日時が出ます。クリックするとそのリポジトリに切り替えてタスクを開きます。「すべて / 未完了 / 完了」の絞り込みと「更新日時 / 作成日時 / ステータス」の並び順は、ブラウザに保存されます。

段階は、未着手・計画中・質問あり・承認待ち（Agent が実装可と判断し未承認）・承認済み（夜間実行待ち）・実行中・検証中・確認待ち・完了の 9 種類で、タスク画面と左の一覧でも同じ表示です。

各プロジェクトでは次を設定・確認できます。

| 項目 | 内容 |
| --- | --- |
| 担当 Agent | 夜間にメモから作るタスクと日報に使う CLI とモデル。初期値は Codex の既定モデル |
| メモ | タイトルと本文を登録・編集・削除。「plan 作成 → 実装を Agent に許可」を付けると夜間にタスク化される。タスク化後は「タスク化済み」から開ける |
| 日報 | 毎朝 6:00 に前日（0:00–24:00）に更新があったプロジェクトだけ作成。日付を押すと HTML をスクリプト無効の枠で表示 |
| 夜間の自動実行 | 0:00 に実行した内容と結果。対象がない夜は記録されない |

毎日 0:00 に、GUI サーバーが各プロジェクトで次の順に実行します。サーバーが止まっていた場合は、次の起動時に逃した回を 1 回だけ実行します（初回起動時はそれ以前の回を実行しません）。

1. 承認済みで、その計画をまだ自動実行していない未完了タスクを実装します。実装済み（検証中）のタスクは、同じ計画の範囲での追加実験として 02 のチャットで実行します。
2. 許可を付けたメモからタスクと専用ブランチを作り、計画を作成します。Agent が実装可と判断したら、メモの許可を承認とみなして実装まで進めます。質問が残った場合は計画中で止めます。

## タスクを作る

左の「＋」からタスク名を入力すると、専用の `task/…` ブランチと作業場所が作られます。大きな作業はタスク画面の「＋ 子タスク」で分割できます。子も作成時に専用ブランチを持ちます。Agent が計画中に分割案を示した場合は、内容を確認して承認すると子タスクになります。

以前のプロジェクトとタスクの記録は、初回起動時にタスク一覧へ移行します。元の `projects/` は移行前の控えとして残ります。移行済みタスクの計画、レポート、資料、会話は同じ `tasks/<id>/` に残ります。

## 01 計画を相談する

目的と達成条件をチャットで伝えます。Agent の質問に答え、保存された `plan.md` と実装可否を確認してください。自分で Markdown を編集した場合は保存し、Agent に再確認を依頼します。Agent が実装可と判断した計画は「計画を承認」で承認でき、その夜 0:00 に担当 Agent が自動で実装します。計画を変更すると承認は無効になり、「承認を取り消す」でも取りやめられます。同じ計画は二度自動実行しません。子タスクを持つ親では実装ボタンを使わず、子タスクを進めます。

チャットの「画像」からファイルを選ぶか、入力欄に画像を貼り付けると、送信前に縮小画像が表示されます。不要な画像は × で外せます。1回に4枚まで、各10 MB以下の PNG・JPEG・WebP・GIF に対応し、画像だけでも送信できます。送信した画像はそのメッセージとともに履歴へ表示され、Agent が内容を確認できます。画像をクリックすると拡大表示できます。

## 実装を始める・中断する

「実装に進む」を押すと確認画面が開きます。今回だけの追加指示を入力でき、保存済み計画は変わりません。Agent がコードを変更し、続けて最初の検証を行います。別の独立したタスクは、それぞれの画面から Agent を続けて起動できます。計画チャット、実装、結果チャットもタスク間で並列に進みます。計画済みの子を複数選び、個別の作業ブランチで一括して並列実行することもできます。親子タスクはブランチの統合先を共有するため同時実行できません。同じ統合先への完了処理は一件ずつ実行され、実行中は別のタスクの完了を受け付けません。

実行中の「中断する」は、選択したタスクの Agent を停止します。途中までのコード変更やコミットは残ります。差分を確認し、必要なら再実行してください。検証が完成していなければ新しいレポートは追加されません。

## 02 結果を確認し、修正を頼む

検証結果は番号付きレポートに保存され、新しいものから表示されます。レポートや資料欄の画像はクリックして拡大表示できます。多数の画像は表示時に順次読み込まれます。数式は LaTeX 記法（文字で数式を書くための記法）の `$...$` または `$$...$$` で表示されます。

数値解析の実験では、評価する場の量（温度や圧力など）の分布を可視化し、レポートに図とその読み取りを必ず載せます。

追加検証、結果への質問、計画の範囲内のコード修正は、02 のチャットに送ります。新しい結果が得られた場合だけレポートが増えます。子を持つ親では、全ての子が完了してから「総括レポートを作成」を使います。

02 のチャットでも、01 と同じ方法で画像を添付できます。添付画像はタスクの資料にも保存されます。

## タスクを完了する

結果と「記録の保存先と変更内容」で差分を確認し、「タスクを完了」を押します。葉タスク（子を持たないタスク）の変更は、確認後に Agent が意味のある単位で一件以上の日本語コミット（Gitに保存する変更のまとまり）を作成し、続けて統合と作業ブランチの削除まで行います。確認画面でコミットの分け方や競合の扱いも指示できます。指示した方針と、成功・失敗の結果、作成したコミット、Agent の報告は 02 の会話に残ります。失敗した場合は、会話に示される診断ファイルで原因を確認できます。途中で止まった場合は、残りの変更を確認して再度依頼できます。

統合では、子タスクは親ブランチへ、最上位タスクは `dev` へ `--no-ff` でマージされます。子を持つタスクは最新の総括を確認してから統合します。競合した場合は Agent が解決を試みます。解決できない場合はマージを中止し、元のコミットとブランチを保持します。そのあと「統合 →」から方針を付けて再度依頼できます。GUI は Agent のマージ結果を検証し、問題があればタスクを完了にせず、会話に理由を残します。

## 保存先と制約

各タスクの計画はタスクフォルダ内の `plan.md`、レポートは `reports/`、画像などは `evidence/`、会話は `chat_plan.json` と `chat_result.json` に保存されます。タスクフォルダはこのアプリの `tasks/` にあり、追加リポジトリではその中のリポジトリ名のフォルダに分かれます。新規タスクの実体フォルダと `by-name/` のリンクには作成日時（日本時間）・作成時の名前・IDが入ります。名前変更後もフォルダ名とリンク名は作成時のままです。既存のID名フォルダも `by-name/` から探せます。移行前のプロジェクト記録も `projects/by-name/` から探せます。ホームのメモ、担当 Agent の設定、日報、夜間の記録は各タスク記録フォルダ直下の `.home/` に保存されます。`tasks/` は Git 管理されません。Git の変更があるタスクや実行中のタスクは削除できません。詳細は[開発・システム設計ガイド](development-guide.md)を参照してください。
